# SuperPoE2 上游资源与生成管线标准

## 1. 目的

本规范定义 SuperPoE2 的数据、图片、翻译、Lua 运行时文件和 UI 素材如何取得、转换、校验和发布。

核心原则：**上游是唯一事实来源，`public/` 是可重复生成并随应用发布的运行时产物。**

更新资源时应更新上游 checkout 并重新运行管线。正常的上游内容更新不应要求手工修改 `public/`，也不应要求修改前端业务代码。

## 2. 适用范围

本规范适用于：

- 天赋树数据、节点、连线、背景、图标和版本信息。
- 职业、升华、装备底材、传奇装备、珠宝、药剂、护符和镶嵌物。
- 主动技能、辅助宝石、装备授予技能、名称、标签、描述和图标。
- 简体中文、繁体中文、韩文等显示翻译。
- PoB Lua 计算代码及其 Data 文件。
- 从上游复制或转换的运行时 UI 素材。

应用源码、npm 依赖和用户保存的构筑不属于资源生成产物，仍按各自的开发和存储规则维护。

## 3. 上游与职责

### 3.1 Path of Building PoE2

目录：`upstreams/PathOfBuilding-PoE2/`

来源：[PathOfBuildingCommunity/PathOfBuilding-PoE2](https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2)

它是游戏语义和计算语义的首要上游，负责稳定 ID、数据关系、天赋树、职业、升华、装备、宝石、技能描述、Lua 计算数据及其自带美术资源。其他上游不得覆盖这些稳定 ID、关系和计算语义。

### 3.2 PoeCharm2

目录：`upstreams/PoeCharm2/`

来源：[Chuanhsing/PoeCharm2](https://github.com/Chuanhsing/PoeCharm2)

它是本地化文本的首要上游。翻译只影响显示和搜索，不得成为业务主键，也不得改变 PoB 原始英文、稳定 ID、导入导出或计算输入。

### 3.3 PoE2DB

来源：[PoE2DB](https://poe2db.tw/)

PoE2DB 是缺失图片和缺失用户可见说明的补充上游。管线可以下载其公开资源并保存为本地生成产物，但应用运行时不得依赖 PoE2DB 热链。

PoE2DB 数据与 PoB 冲突时：

1. ID、分类、关系和计算字段以 PoB 为准。
2. PoB 缺少图片时才使用 PoE2DB 图片。
3. PoB 缺少用户可见描述时才使用 PoE2DB 描述，并在 manifest 中记录来源。

### 3.4 WeGame

WeGame 是构筑导入来源，不是全局资源事实来源。导入结果携带的精确图片 URL 仅可用于该构筑的即时显示或进入离线缓存，不得反向覆盖全局装备、技能或翻译目录。

`docs/design/references/wegame-poe2/` 只用于设计研究，除非明确纳入生成管线，否则不是运行时资源。

## 4. 不可变边界

- `upstreams/` 下的仓库视为只读 checkout，不在 SuperPoE2 中直接修改。
- `upstreams/` 不提交到 SuperPoE2 仓库。
- `public/` 下由管线生成的 JSON、图片和 Lua bundle 禁止人工修补。
- 修复缺图、缺字段或错误映射时，应修改解析器、转换器或校验器，然后重新生成。
- 生成产物必须提交，保证发行版和新机器不需要上游仓库、Python、LuaJIT 或联网即可运行。

## 5. 统一数据模型

所有领域数据必须遵守以下规则：

1. 使用 PoB 稳定 ID 作为规范主键。
2. 英文名称、中文名称、`gemId`、`skillId`、`variantId`、底材名称等只作为字段或别名。
3. 查询顺序固定为稳定 ID、领域 ID、变体 ID、英文名称、规范化别名。
4. 不使用中文文本作为导入导出、计算或持久化主键。
5. 同一实体只保留一条规范记录，图片、描述、翻译和来源通过该记录关联。
6. 兼容期可以继续输出旧 JSON，但旧文件必须由统一 catalog 派生，不能形成第二份事实来源。

目标 catalog 至少包括：

- `tree`：树版本、节点、连接线、职业和升华。
- `items`：底材、传奇、装备类型、镶嵌物和图片。
- `skills`：主动技能、辅助宝石、授予技能、描述、标签和图片。
- `translations`：语言 manifest 和英文到本地化文本的映射。
- `runtime`：Lua bundle 与所需 Data 文件。

## 6. 资源解析优先级

### 6.1 图片

1. PoB 上游内与稳定 ID 或原始资源路径明确关联的图片。
2. PoE2DB 中与同一 PoB 实体明确关联的图片。
3. 已验证兼容的上一资源版本图片。
4. 按资源类型生成的统一占位图。

禁止按模糊名称静默覆盖已命中的稳定 ID 图片。使用回退或占位图时，必须记录到 manifest 和覆盖率报告。

### 6.2 描述和属性

1. PoB 数据定义和 `Data/Skills/*.lua`。
2. PoE2DB 对应实体页面，仅补 PoB 缺失的用户可见描述。
3. 无可靠来源时保存为 `null`，UI 明确显示暂无描述。

装备授予技能的本地化描述由 PoE2DB `cn/tw/kr` 页面补充，但仍以 PoB `skillId`、英文名称和别名关联。译文作为 `localizedDescriptions` 字段进入统一技能 catalog，不写入 PoeCharm2 上游，也不覆盖 PoB 英文原文。

内部、隐藏、怪物或子技能可以没有用户描述，但必须与用户可选择的主动技能和辅助宝石分开统计。

### 6.3 翻译

1. PoeCharm2 对应语言和领域文件。
2. 项目自身的 UI 文案。
3. 未命中时显示 PoB 英文原文。

不得为了提高表面翻译率而在生成产物中人工写入译文。

## 7. 管线契约

全量入口统一为：

```powershell
npm run pipeline:all -- 0_5
```

最终的 `pipeline:all` 必须按确定顺序完成：

1. 检查依赖和两个上游目录。
2. 记录上游 commit、工作区状态和目标游戏数据版本。
3. 生成天赋树、职业、升华、装备、技能、翻译和 Lua bundle。
4. 转换 PoB 本地图集和 UI 素材。
5. 从 PoE2DB 补齐缺失图片或描述。
6. 执行引用、覆盖率、版本和文件完整性校验。
7. 生成全局资源 manifest 和覆盖率报告。
8. 所有阶段成功后，原子替换正式生成目录。

单领域命令用于开发和诊断，例如 `pipeline:tree`、`pipeline:items`、`pipeline:skills`、`pipeline:translations` 和 `pipeline:lua`。发布资源时必须以 `pipeline:all` 的结果为准。

`--dry-run` 不得写入正式目录。任一必需阶段失败时，管线必须返回非零状态，并保留上一套可用产物。

## 8. Manifest 标准

全局 manifest 应至少记录：

- manifest schema 版本和目标 PoE2 数据版本。
- PoB、PoeCharm2 的上游 URL、commit 和 dirty 状态。
- PoE2DB 同步时间及使用的目录页。
- 每类实体、图片、描述和翻译数量。
- 缺失、旧版本回退和占位资源清单。
- 每个生成文件的相对路径、大小和内容 hash。

构建不得把本机绝对路径写入运行时 manifest。

## 9. 完整性门禁

管线完成前必须验证：

- JSON 可解析且符合 schema。
- manifest 中每个本地文件真实存在且非空。
- 每个用户可见主动技能和辅助宝石都有稳定 ID、名称和可显示图片。
- 上游存在的用户可见描述已进入 catalog。
- 每件可装备底材、传奇、药剂、护符、珠宝和镶嵌物有图片或明确 fallback。
- 天赋节点、connector、orbit、背景和 sprite 引用可以解析。
- 翻译未命中时能稳定回退英文。
- Lua manifest 引用完整，并通过固定构筑的计算对齐测试。
- 至少使用一个真实 PoB Code 验证职业、升华、天赋、装备、技能和辅助宝石的引用覆盖。

覆盖率必须区分用户可见实体与内部实体。内部技能缺少描述不能掩盖用户可见宝石缺图，也不能让完整性检查产生无意义失败。

## 10. 版本与回退

- 天赋树运行资源只保留产品约定的最近两个版本。
- 数据关系和坐标不得跨版本回退。
- 图片仅在规范资源路径或稳定 ID 一致时允许跨版本回退。
- 每次回退必须保留来源版本，不得伪装成当前版本原生资源。
- 新版本正式发布前，必须完成实际 PoB Code 的导入和显示验证。

## 11. Git 与发布

- 提交管线代码、schema、测试、manifest 和全部运行时生成产物。
- 不提交 `upstreams/`、`.cache/`、临时下载文件和用户构筑。
- 资源更新提交应说明上游 commit、目标版本、覆盖率和 fallback 变化。
- CI/发行工作流使用仓库中已提交的生成产物，不在普通应用构建阶段临时联网抓取资源。

## 12. 运行时降级边界

运行时资源分为两类：

- 核心数据：`tree-web-{version}.json`。文件缺失、JSON 损坏或缺少 `version/constants/classes/nodes/groups` 时必须显示明确错误，不能静默显示空天赋树。
- 增强资源：物品和技能图片索引、装备底材、镶嵌物详情、翻译 CSV、sprite、connector、orbit、UI 装饰以及 Lua 计算 bundle。

增强资源缺失时必须限制影响范围：

- 图片路径不存在时隐藏破损图片，并显示首字、符号、基础框线或无贴图节点。
- 可选 JSON 缺失、损坏或 schema 较旧时归一化为空索引，装备、技能和天赋基础交互继续可用。
- 翻译 manifest 或单个 CSV 缺失时显示英文原文。
- 当前版本 connector、orbit 或 sprite 缺失时可回退兼容版本；两边均缺失时跳过该视觉层。
- Lua bundle 缺失时只禁用本次计算并返回明确错误，不影响构筑导入、浏览和编辑。

兼容降级只用于已发布应用抵御资源缺失，不能替代发布前完整性门禁。资源管线发现应有资源缺失时仍必须失败。

## 13. 当前实现审计

当前实现中，以下部分已经符合：

- 两个 `upstreams` 仓库按本地只读 checkout 管理并被 Git 忽略。
- `public/` 运行资源随仓库提交，桌面应用运行不要求资源管线依赖。
- PoE2DB 图片下载到本地，技能和物品显示不使用运行时热链。
- 天赋树、翻译、装备底材、技能图标和 Lua bundle 均已有独立生成步骤。
- `pipeline:all` 已编排翻译、镶嵌物、装备底材、UI、天赋树、物品、技能、Lua bundle 和最终校验阶段。
- 技能信息已归并到 `public/data/skill-catalog.json`，以 PoB 技能 ID 为主键，统一关联图片、描述、标签和来源。
- `public/data/resource-manifest.json` 已记录上游版本、覆盖率、警告以及运行时文件的大小和 SHA-256。
- 发布前完整性校验已集中到 manifest 生成阶段；缺失本地引用或必需资源时，管线会返回非零状态。

当前仍需完成的主要架构项只有：部分生成脚本会直接写正式目录，尚未统一为“临时目录完整生成并校验成功后，再原子替换正式产物”。在此项完成前，生成失败时应检查工作区差异，不得通过手改生成文件绕过校验。
