# 剧情指引内容维护与编辑器

## 当前实现

主窗口「剧情指引」位于「交易中心」下方，直接显示第一章，使用章节与路线、地图、详情三栏布局。章节、地图、媒体全部随应用打包。现有五份章节共 92 个节点，均已绑定真实游戏区域 ID。

`D:/sources/Poe2Storyguide` 仅作为原始内容、地图和媒体的只读参考；SuperPoE 使用原生 React 页面。原始节点 ID、地图引用、坐标、常规说明、步骤和奖励已保留；随包数据已移除赛季任务、赛季奖励及攻略中的赛季玩法说明。可选赛季字段仍兼容旧草稿的导入与导出。没有通关打勾或持久化剧情进度，编辑器集成在同一页面。

目前 `act5` 是「间章」，不能当作游戏未来的第五章覆盖。未来真实第五、六章应使用独立唯一 ID。

## ID 与名称

`node.id` 是稳定内容标识，原有 `node_1` 等 ID 不随改名或顺序调整而改变。`mapId` 引用同章 `maps[].id`，不是游戏区域 ID。`areaId` 必须使用日志和 PoE2DB 的真实区域 ID，区分大小写，不能从标题或顺序猜测。

第四章 `node_3` 对应 `G4_2_2`（Journey’s End），`node_4` 对应 `G4_1_1`（Isle of Kin）。第二章 `node_3` 与 `node_7` 都对应 `G2_3`，保留这两次访问。自动定位先按 `flowOrder` 匹配，再按节点数组查找支线，因此重复区域优先主线首次出现的节点。

`names.international` 为国际服中文名称（目前来自 PoE2DB 繁中），`names.chinese` 为国服简中名称，不是英文与中文的区分。缺失时回退到原始 `title`。补名称不会覆盖原攻略标题。

## 页面内编辑

1. 选择章节后点击「编辑内容」。编辑期间暂停自动跟随，便于拖动与定位。
2. 点击节点编辑，可直接拖动或输入 0–100 百分比坐标。地图显示十等分网格；方向键微调 0.1，Shift 加方向键调整 1。
3. 维护标题、两服名称、区域 ID、地图、说明、提示、奖励、标签、赛季奖励、封面、步骤与图片。区域 ID 提供快照候选，可填充已知名称。
4. 主线加入和排序同步更新 `flowOrder` 与主线 `next`。支线单独指定后继。新增为支线；复制保留内容，但清空区域 ID 与后继，避免误用日志绑定。
5. 整章 JSON 编辑器支持地图清单、赛季任务及自定义元数据。导入先校验嵌套结构；语义错误可在页面修复，存在错误时禁止导出。
6. 「导出章节」保存完整 JSON，检查文件后替换仓库对应章节。地图和媒体另行放入 `public/story-guide/`，JSON 不内嵌图片。

草稿仅保存在当前应用进程内存，切换页面仍保留；重载或退出会丢失未保存文件的草稿。页面不会直接写源码目录。导出触发下载后会清除未导出标记，务必确认文件已保存。

删除节点会移除主线引用、修复主线后继，将指向该节点的支线衔接到其后继，并避免修复产生自身循环。校验通过仍需人工确认攻略路线符合游戏。

## 游戏截图与 AI 草稿

将自己的截图放入 `public/story-guide/maps/` 或媒体子目录。`/maps/example.png`、`maps/example.png`、`/story-guide/maps/example.png` 均相对于 `public/story-guide/`。禁止网络地址、磁盘绝对路径、路径穿越、反斜杠和查询参数，文件名大小写应与文件一致。

让 AI 根据 PoE2DB 生成草稿时，要求保留现有 `node.id`、`mapId` 和未知元数据；新增 ID 不得重复。每张地图需要 `id/title/image`，每个节点需要 `id/mapId/title/description/x/y/next`，结尾 `next` 为 `null`。`flowOrder` 是节点 ID 数组，主线 `next` 必须与其后继一致。真实 `areaId` 无法确认时留空，不编造。坐标先粗略定位，再导入编辑器拖动校正；常规奖励、步骤与支线保留，不添加赛季任务、赛季奖励或赛季玩法说明。

「导入 JSON」替换当前章节草稿，限制 8 MB，不能与其他现有章节使用相同 ID。新章节正式接入仍需修改文件清单。图片不放入 JSON。

地址参数 `debug=1`（也支持 hash 查询参数）开启坐标调试：点击地图显示红标，并在控制台输出一位小数坐标，不修改节点。`edit=1` 可直接进入编辑状态。

## 快照与绑定维护

日常运行完全使用本地快照。维护时在项目根目录执行：

```powershell
node scripts/story-guide-snapshot.mjs
node scripts/story-guide-snapshot.mjs --apply
```

默认仅获取绑定表中尚未收录的区域；`--apply` 在全部绑定都有核验记录后补齐章节缺失的 `areaId` 与名称，保留人工内容。已有区域 ID 与绑定表冲突会报错，应核对后人工处理。绑定数组按稳定 `node_N` 的数字部分对应，而非 `nodes` 数组的位置。

```powershell
node scripts/story-guide-snapshot.mjs --refresh
```

`--refresh` 重新核验全部区域。脚本利用 PoB `WorldAreas.lua` 基础名称生成 PoE2DB cn/tw 地址，并要求页面包含精确区域 ID 的标题证据。网络失败保留旧记录，因此命令结束不代表每条均刷新成功，需看输出及差异。新区域还需确认 PoB 数据已有对应项。

## 日志跟随与计时器

Electron 复用现有日志解析器，通过 `story-guide:area-changed` 独立广播；页面订阅 `pob2StoryGuide.onAreaChanged`，通过 `getCurrentArea` 获取最近区域。无需启动剧情计时器，不写计时或通关状态。

已知区域切换对应章节、地图和节点并高亮；未知 ID 忽略，保留上一次有效位置。关闭自动跟随可手动浏览，当前区域标识仍更新。较旧时间戳事件忽略。计时器模式、暂停、章节计时、重置与 SQLite 统计继续由原计时器管理。

## 新增未来章节

1. 在 `chapters/` 新建完整 JSON，使用不与间章冲突的唯一 ID。
2. 添加本地地图及媒体。
3. 在 `manifest.json` 设置顺序、显示名、文件路径；当前加载器按文件名从章节目录读取，文件名应与 ID 对应。
4. 核实区域 ID、两服名称、路线和奖励；使用维护脚本时增加稳定节点绑定。
5. 更新回归测试中的章节和节点数量断言，运行验证并实际打开新章节。

常规新增章节只涉及清单、内容和资源，无需修改页面路由或新增章节专属组件。

## 验证

页面顶部的“重新加载数据”会绕过缓存重新读取随包章节 JSON，成功后替换所有章节的会话草稿，保留仍存在的当前章节、节点及地图。有未导出的修改时先确认；读取或解析任一章节失败则保留全部现有内容和草稿。开发环境读取当前源码中的章节文件，安装版读取当前版本随包的数据；该按钮不下载新版本，也不自动读入编辑器导出的外部文件。

地图操作：按住鼠标左键拖动背景可平移地图，滚轮以鼠标所在位置为中心缩放（100%–250%）；顶部加减按钮以视口中心缩放，百分比按钮恢复 100%。地图未超出视口的方向不产生多余位移。缩放不会触发选中节点的自动定位；手动选择其他区域或日志跟随切换区域时，仍会把节点移入视野。拖动后的松手不会误选节点。

编辑模式中，拖动节点只修改该节点的百分比坐标，拖动背景仍用于平移；节点也支持方向键微调，Shift 加大步长。鼠标取消或窗口失焦时停止拖动，不提交未完成的坐标修改。测量模式单击取坐标，拖动不产生测量标记。
