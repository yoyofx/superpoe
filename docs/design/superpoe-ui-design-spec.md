# SuperPoE 桌面端 UI 设计规范

> 状态：已定稿  
> 适用范围：SuperPoE Electron 桌面应用  
> 布局策略：连续自适应；`1440 x 900`、`1280 x 720` 仅作为回归验证视口

## 1. 产品定位

SuperPoE 是面向《流放之路 2》深度玩家的离线构筑规划工具。核心使用场景是反复新建、导入、编辑、比较和计算 BD，而不是游戏官网、资讯站或营销页面。

应用启动后直接进入可工作的“构筑中心”，不设置 Landing Page、Hero 区域、宣传语或功能介绍页。

## 2. 设计目标

- 保留 Path of Building 的高信息密度、操作效率和克制感。
- 使用暗黑档案馆式视觉语言，让应用具备 PoE2 世界观下的辨识度。
- 在装备纸娃娃、一级边框和标题装饰中参考 WeGame PoE2 构筑页的古旧石板、黑铁和暗金质感。
- 高频操作区保持安静、清晰，避免装饰纹理干扰数据阅读。
- 所有构筑编辑页面使用统一导航、面板、控件和状态体系。

## 3. 设计原则

### 3.1 工作台优先

- 第一屏必须提供新建、导入、搜索和打开构筑的能力。
- 主操作保持在一到两次点击内，不将常用功能藏入多层菜单。
- 表格、列表和检查器优先于大卡片和展示型布局。

### 3.2 装饰服从信息

- 古旧金属、石板、雕刻和暗金装饰只用于一级框架、装备槽、标题和重要状态。
- 普通表格、表单和高频工具栏使用低对比深灰界面。
- 不使用玻璃拟态、大面积渐变、装饰性光斑、过大圆角和悬浮卡片堆叠。

### 3.3 状态明确

- 保存、导入、计算、编辑模式和武器组必须有可辨识状态。
- 不能只依赖颜色表达状态，同时使用文字、图标或边框。
- 错误显示在对应操作区域，不使用浏览器原生弹窗。

### 3.4 数据与显示分离

- UI 翻译不改变职业、升华、节点、装备和技能的内部 ID。
- 视觉改版不改变构筑保存格式、PoB Code、WeGame 导入结果和计算输入。
- 装备视图只调整结构和视觉，保留现有装备解析、图片匹配、孔位和武器组逻辑。

## 4. 视觉系统

### 4.1 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 应用背景 | `#090B0C` | 最外层背景 |
| 主工作区 | `#111311` | 画布外的主要操作面 |
| 次级面板 | `#181917` | 检查器、工具区 |
| 控件背景 | `#151714` | 输入框、按钮、下拉 |
| 普通分隔线 | `#454137` | 低对比结构线 |
| 强调边框 | `#88764F` | 当前选择和一级标题 |
| 主文字 | `#D8D1C3` | 主要数据和标题 |
| 次要文字 | `#8C877D` | 注释、时间、辅助信息 |
| 暗金强调 | `#C4A663` | 选择、重要操作 |
| 信息蓝 | `#6F9FC9` | 物品词缀、信息状态 |
| 翡翠绿 | `#3DDB78` | 正向变化、武器组 II |
| 猩红色 | `#E6424F` | 错误、负向变化、武器组 I |

大面积背景不得使用鲜艳颜色。红、绿、蓝只用于状态、数据差异和武器组识别。

### 4.2 尺寸

| 元素 | 尺寸 |
| --- | --- |
| 顶部应用栏 | `52px` |
| 编辑器 Tab 栏 | `42px` |
| 左侧栏 | `228-260px` |
| 右侧检查器 | `320-380px` |
| 普通控件高度 | `30-34px` |
| 图标按钮 | `32 x 32px` |
| 控件圆角 | `4px` |
| 重复项最大圆角 | `6px` |
| 装备孔 | `22 x 22px` |
| 装备孔间距 | `4px` |
| 正文 | `12-14px` |
| 面板标题 | `14-16px` |
| 页面标题 | `18-20px` |

字体不随视口宽度缩放。固定格式区域通过网格轨道、最小宽度和纵横比保持稳定。应用不要求用户使用指定分辨率，布局根据实际窗口宽高连续调整。

### 4.3 图标与控件

- 通用操作使用 Lucide 风格图标。
- 撤销、重做、搜索、保存、缩放、适配视图等使用熟悉图标，不重复显示冗余文字。
- 不熟悉的图标按钮必须提供 tooltip。
- 模式选择使用分段控件，二元设置使用开关或复选框，选项集合使用菜单或下拉。
- 文字按钮只用于“新建构筑”“导入构筑”“创建构筑”等明确命令。

## 5. 应用信息架构

```text
构筑中心
├── 新建构筑向导
├── 统一导入构筑
└── 构筑编辑器
    ├── 天赋
    ├── 装备
    ├── 技能
    └── 计算
```

Tab 切换不得丢失当前编辑状态。任何天赋、装备和技能修改都立即标记为“有未保存修改”，同时自动保存草稿。

## 6. 构筑中心

构筑中心是应用启动后的默认页面。

### 6.1 顶部应用栏

- 左侧：SuperPoE 标识、当前数据版本及状态。
- 中部：构筑搜索框。
- 右侧：语言切换、设置和帮助。

### 6.2 命令区

主内容顶部只保留两个一级命令：

- 新建构筑
- 导入构筑

### 6.3 最近打开

使用紧凑横向列表，展示职业图标、构筑名称、升华和最近打开时间。不得使用大型营销卡片。

### 6.4 我的构筑

使用表格式列表，包含：

- 构筑名
- 职业 / 升华
- 数据版本
- 天赋点数
- 装备数量
- 修改时间
- 来源
- 更多操作

来源以细小状态标签表示：本地、WeGame 导入、PoB Code 导入。每行支持打开、复制、重命名和删除。

空状态只显示“新建构筑”和“导入构筑”，不添加说明性大段文案。

## 7. 新建构筑向导

使用居中模态窗口，不跳转到独立页面。

### 7.1 步骤

1. 职业
2. 升华
3. 基础信息

职业使用紧凑图标列表，显示职业名称和升华数量。升华步骤允许“稍后选择”。基础信息包含构筑名称、天赋树版本和是否从空白天赋盘开始。

底部固定显示：取消、上一步、下一步、创建构筑。当前步骤只显示有效操作。

## 8. 统一导入构筑

使用一个模态窗口，通过顶部 Tabs 支持：

- PoB Code
- WeGame 分享链接
- 构筑 JSON

每个 Tab 提供对应输入控件和解析按钮。解析成功后进入预览状态，不立即覆盖任何构筑。

预览内容包含职业、升华、天赋树版本、分配节点数、武器组节点数、装备数量、技能组数量和来源。

底部操作：

- 作为新构筑导入
- 替换当前构筑
- 取消

“替换当前构筑”属于破坏性操作，必须再次确认。解析错误使用紧凑错误条显示原因和可执行建议。

## 9. 构筑编辑器

### 9.1 顶部第一行

- 左侧：返回构筑中心、职业图标、构筑名称、保存状态。
- 中部：构筑数据版本选择。
- 右侧：保存、导入、导出和更多菜单。

保存状态必须覆盖：已保存、有未保存修改、正在保存、保存失败。

### 9.2 顶部第二行

使用固定 Tabs：

- 天赋
- 装备 `14`
- 技能 `8`
- 计算

每个 Tab 使用小图标和必要数量，不使用折叠菜单代替主导航。

## 10. 天赋视图

### 10.1 左侧栏

- 职业下拉
- 升华下拉
- 节点搜索
- 编辑模式
- 武器组：全部、武器组 I、武器组 II
- 当前天赋点
- 撤销、重做

### 10.2 主画布

- 继续使用现有 Pixi 天赋树渲染。
- 支持以鼠标为中心缩放、拖拽、hover 和点击分配。
- 武器组 I / II 使用高辨识度红色和绿色。
- 当前升华盘继续显示在职业中心区域。
- 搜索结果支持定位、高亮和回车循环切换。

### 10.3 右侧检查器

- 选择节点时：名称、属性、前置路径和分配状态。
- 搜索时：搜索结果列表和当前结果位置。
- 未选择节点时：当前构筑摘要。

画布右下角显示缩放、适配全树和当前缩放百分比。

## 11. 装备视图

装备视图改为完整 Tab 页面，不使用右侧浮层覆盖主内容。

### 11.1 改造边界

本轮只调整装备页面布局、边框、背景、字体、选择状态和详情呈现，不修改：

- 装备 XML/构筑数据解析
- 物品图片索引与匹配
- 装备组和武器组数据
- Rune、Soul Core、Idol 解析
- 孔位数量、顺序和翻译
- 导入、导出和计算逻辑

### 11.2 页面布局

- 左侧：装备组 I / II、装备配置选择、装备完整度和简要汇总。
- 中间：纸娃娃式装备布局。
- 右侧：固定装备详情检查器。
- 可选底部区域：装备变化结果和完整孔位列表。

### 11.3 纸娃娃区域

- 使用 WeGame 风格的古旧石板、暗金细边和明确装备槽。
- 武器、护甲、饰品、药剂和护符位置固定，动态内容不能改变布局尺寸。
- 每件装备显示原始物品图和稀有度边框。
- 装备名称仅在空间允许时显示；紧凑视口通过 tooltip 显示完整名称。
- hover 只轻微提亮，选中使用暗金描边，不缩放装备槽。

### 11.4 装备孔

- 孔覆盖在物品图中央。
- 每行两个，尺寸 `22px`，间距 `4px`。
- 整组孔水平、垂直居中。
- 奇数数量时最后一个孔单独居中。
- 孔内只显示 Rune、Soul Core、Idol。
- 缺少资源时显示精简符号和 tooltip。
- 技能宝石不属于装备孔，不得在此显示。

### 11.5 装备详情

固定右侧检查器显示：

- 原始物品图
- 名称和稀有度
- 底材与物品等级
- 隐式和显式属性
- 孔位列表
- 每个孔的图标和名称
- 装备变更对关键计算结果的影响

武器组 II 切换后只替换对应武器槽，其余装备保持不变。

## 12. 技能视图

技能组独立于装备孔。

- 左侧：技能组列表、主技能、辅助数量和启用状态。
- 中间：当前主技能与辅助技能关系。
- 右侧：等级、品质、变体和计算关联信息。

主技能可使用较大图标，辅助技能保持紧凑。不得将技能组伪装成装备镶嵌孔。

## 13. 计算视图

页面面向比较和诊断，不做营销型仪表盘和复杂图表。

顶部显示计算按钮、计算状态和最后计算时间。结果按以下顺序分区：

1. 防御：生命、能量护盾、护甲、闪避、抗性。
2. 进攻：主技能 DPS、暴击、攻击/施法速度、元素伤害。
3. 资源：魔力、精神、药剂、护符。
4. 警告：缺失条件、异常输入和计算提示。

开启“对比上次结果”后，在对应数值右侧显示紧凑增减值，不增加复杂趋势图。

## 14. 菜单、模态与 Tooltip

- 菜单靠近触发控件展开，并限制在可视区域内。
- 模态窗口使用统一标题、内容和固定底部操作区。
- 删除、覆盖导入和关闭未保存构筑必须确认。
- Tooltip 使用 DOM 浮层，不能阻挡鼠标操作。
- 图标 tooltip 只描述命令，不显示大段使用说明。
- 应用界面不显示后端、Lua、WASM、资源抓取等实现概念。

## 15. 自适应规则

界面不绑定固定分辨率。以下视口是回归测试基准，不是运行要求；两个基准之间及以外的窗口尺寸通过弹性网格、`clamp()`、固定纵横比和面板重排连续适配。

### 15.1 `1440 x 900`

- 完整显示左右侧栏、纸娃娃和详情。
- 顶部命令保留图标和文字。
- 构筑中心显示完整表格列。

### 15.2 `1280 x 720`

- 左侧栏收窄到 `228px`，右侧检查器收窄到 `320px`。
- 次要按钮只保留图标和 tooltip。
- 构筑表格隐藏优先级较低的“来源”或“装备数量”列。
- 装备纸娃娃按固定纵横比缩放，不改变槽位相对位置。
- 不允许文字、按钮、装备槽、画布控件和检查器互相遮挡。

## 16. 关键状态稿

高保真设计和实现验收至少覆盖：

1. 构筑中心正常列表和最近打开。
2. 构筑中心空状态。
3. 新建构筑职业选择步骤。
4. WeGame 导入解析成功预览。
5. 导入解析失败。
6. 天赋编辑器默认状态。
7. 天赋搜索和武器组编辑状态。
8. 装备视图默认状态、装备选中和武器组 II。
9. 计算完成、计算警告和计算失败。
10. 已保存、未保存、正在保存和保存失败。

## 17. 实施顺序

1. 建立全局颜色、间距、边框、字体和控件变量。
2. 重构应用外壳、构筑中心和编辑器双层顶部导航。
3. 在不改业务逻辑的前提下重构装备页面 DOM 和样式。
4. 整理天赋页左右侧栏，保持 Pixi 渲染逻辑不变。
5. 重构技能和计算页面。
6. 统一新建、导入、确认、错误和保存状态。
7. 在 `1440 x 900` 和 `1280 x 720` 完成截图与交互验收。

## 18. 验收标准

- 第一屏为构筑中心，所有核心工作流可到达。
- 六个核心页面使用一致的应用框架和设计变量。
- 装备显示、图片匹配、孔位、武器组、导入导出和计算行为无回退。
- 天赋树缩放、拖拽、搜索、编辑和 tooltip 无回退。
- 所有关键状态均有明确视觉反馈。
- 两档目标分辨率无文本、控件和内容重叠。
- 控制台无新增错误和资源加载失败。
